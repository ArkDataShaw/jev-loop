Field notes on building loops around a decision model.

Jev answers typed questions about a state with calibrated probabilities. It never writes text. That makes it cheap enough to sit inside a loop that runs on every screen, every spoken word, every agent turn. These are the lessons that cost someone something, with the numbers attached.

The loop

Every system on this site has the same four beats. Code owns three of them. The model owns one, and it is the only one that costs money.

ObserveCapture the state as text or JSON: a page diff, a transcript, a terminal tail, a record. Code does this.
AskOne request, many typed questions: yes or no, pick one, score on a rubric. Answers come back as probabilities in about 300 ms.
DecideThresholds and policy live in code. Act, wait, ask a human, or ignore. Low confidence is a branch, not an error.
VerifyCheck the effect, not the action. Replay, re-read, or hand the claim to a session that has never seen it.

WhatValueNote

Start in thirty minutes

Before building anything, run the closest thing that already exists against your own app and read its report.

  1. Get a key from the TypeSafe console and export it as TYPESAFE_API_KEY. Never put it in a file you commit.
  2. Point jevqa at a deployed build with the spec the app was built from. It explores on its own and writes a report with a screenshot per finding. 
    uvx jevqa run https://your-staging-url --spec README.md --steps 50
  3. Read missing features first. They are the most reliable findings. Skim the rest in ninety seconds and expect about one in eight to be a real defect.
  4. Add the two things the tool does not do: a second session that tries to disprove each finding, and a run verdict that publishes nothing when the app was never reached.
  5. Keep three to five journeys the questions were never tuned on. Score every change against those, not against the ones you tuned.
  6. Only then decide how much persona and goal-driven behaviour to build on top. The judge is rarely the limit; the actor is.
